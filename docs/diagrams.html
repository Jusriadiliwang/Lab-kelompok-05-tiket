Sequence Diagram — Race Condition

Simulasi 1000 user berebut 1 kursi secara bersamaan. Redis atomic SET NX EX menjamin hanya satu yang menang.

Race Condition — 1000 User, 1 Kursi
sequence
sequenceDiagram actor U1 as User-1 (menang) actor U2 as User-2 (kalah) participant TS as ticket-service participant Redis par Concurrent request U1->>TS: POST /tickets/lock { seatId: A1 } U2->>TS: POST /tickets/lock { seatId: A1 } end TS->>Redis: SET lock:seat:A1 user1 NX EX 600 Redis-->>TS: OK → U1 menang TS->>Redis: SET lock:seat:A1 user2 NX EX 600 Redis-->>TS: nil → U2 KALAH (NX = only if Not eXist) TS-->>U1: 201 { reservationId, expiresAt } TS-->>U2: 409 Conflict { message: "Seat already reserved" }

Lapisan Anti-Oversell

Empat lapisan perlindungan berlapis yang memastikan satu kursi hanya bisa terjual satu kali, bahkan saat ribuan request bersamaan atau terjadi bug di satu lapisan.

L1
Rate Limit — API Gateway / Redis Sliding window counter per user (10 req/s pada /tickets/lock). Melindungi backend dari abuse & bot.
L2
SET NX EX — Redis Distributed Lock Operasi atomic O(1). Hanya satu request yang bisa sukses walau ribuan request bersamaan. TTL otomatis melepas kursi bila tidak dibayar.
L3
INSERT reservation — PostgreSQL Persistence Data reservasi dicatat permanen ke database. Hanya berjalan setelah Redis lock berhasil diperoleh.
L4
UNIQUE seat_sold constraint — PostgreSQL Last-Resort Constraint UNIQUE pada kolom seat_id di tabel seat_sold. Jaminan terakhir — tidak mungkin ada dua record untuk kursi yang sama.
